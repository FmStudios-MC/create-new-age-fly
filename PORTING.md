## Decisions

- **Single source set** (as upstream). Client classes guarded with `@Environment(EnvType.CLIENT)`.
- **No Registrate shim.** Registration is rewritten in Create Fly's vanilla style (`Blocks.register`,
  `Registry.register`). Only ~1,150 lines across `CNABlocks/Items/BlockEntityTypes`. Tags, blockstates,
  models and loot tables were generated by Registrate and are committed under `src/generated/resources`.
- **ESL → Team Reborn Energy** (`teamreborn:energy`, jar-in-jar). ESL was modelled on it; the API maps nearly 1:1, transactions come from Fabric's transfer API.
- **Datagen code** (`data/`, `*BlockStateGen`) is not needed at runtime and will be excluded from compilation rather than ported.
- `_neoforge_old/` keeps the NeoForge entrypoints/platform code for reference until their Fabric equivalents exist, then gets deleted.

## Things learned about Create Fly so far

- Addon hook: entrypoint `create_plugin` → `com.zurrtum.create.api.registry.CreateRegisterPlugin` (`onBlockRegister`, `onFluidRegister`, …).
- Block entity types: `new BlockEntityType<>(factory, Set<Block>)`, factory is `(pos, state)` – no type argument.
- Behaviours are split: server side `Server*ScrollValueBehaviour` on the block entity, client side `*ScrollValueBehaviour` registered separately (see Create Fly `client/AllBlockEntityBehaviours`). Goggle info (`IHaveGoggleInformation`) is client-only.
- Config: Catnip `ConfigBase` / `Builder` under `com.zurrtum.create.catnip.config` replaces NeoForge `ModConfigSpec`.

## Tools

- `tools/createfly-classes.txt` – every class in the Create Fly jar we compile against. Regenerate after a Create Fly bump.
- `tools/remap_imports.py` – maps Create/Catnip/Ponder/Flywheel references to Create Fly packages (dry run by default, `--write` to apply).
